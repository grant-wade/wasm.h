# Changelog

All notable changes are documented here. This project follows Semantic Versioning.

## [Unreleased]

### Changed

- Struct and array layouts are computed once per type, and collections trace only fields and elements that can hold references.
- `struct.get`, `struct.set`, `array.get`, `array.set`, `array.len`, the i31 instructions, `ref.func`, and saturating truncations run inside the interpreter loop.
- References stored through `wasm_module_global` or `wasm_global_import_t.value` must have the global's type.
- `ref.test`, `ref.cast`, `br_on_cast`, `br_on_cast_fail`, and the custom descriptor casts run inside the interpreter loop, and casts to struct and array types take constant time.

### Fixed

- Freeing a module after an allocation failure left its GC objects without types, and collections stopped tracing their fields.
- `br_on_cast_desc_eq` and `br_on_cast_desc_eq_fail` cost two units of fuel and could stop between their cast and their branch.
- `wasm_table_set` and `wasm_table_grow` on an imported table checked values against the exporting module's types and could store an object of the wrong type.
- Active element segments, `table.init`, and `table.copy` on imported tables of concrete reference types rejected some valid modules and accepted some invalid ones.
- `wasm_table_type` and `wasm_table_reftype` described an imported table with the exporting module's type indices.

## [2.0.0] - 2026-10-19

### Breaking

- `wasm_init` and `wasm_destroy` are removed, and `wasm_runtime_new` returns NULL when the configuration is invalid or allocation fails.
- Runtime state functions are `wasm_runtime_set_fuel`, `wasm_runtime_fuel`, `wasm_runtime_call_depth`, `wasm_runtime_call_frame`, and `wasm_runtime_backtrace`, replacing `wasm_set_fuel`, `wasm_get_fuel`, `wasm_get_call_stack_depth`, `wasm_get_call_frame_info`, and `wasm_dump_backtrace`.
- A runtime's proposals are set at creation by `wasm_config_t.features`, a 64-bit mask of `WASM_FEATURE_*` bits defaulting to `WASM_FEATURES_ALL`, and `wasm_runtime_new` returns NULL for bits outside it.
- Every implemented proposal is enabled by default, including wide arithmetic, custom page sizes, compact imports, threads, stack switching, and custom descriptors; `WASM_FEATURES_STANDARD` enables only standardized proposals.
- `WASM_FEATURE_*` constants are `uint64_t`.
- `wasm_enable_feature`, `wasm_disable_feature`, `wasm_enable_all_features`, `wasm_runtime_set_enabled_features`, and `wasm_runtime_enabled_features` are removed; `wasm_runtime_features` returns a runtime's features.
- In Zig, `Config.features` is a `Features` backed by `u64` whose fields default to true, with `Features.all` and `Features.standard` constants, and `Runtime.setFeatures`, `enableFeatures`, `disableFeatures`, and `enableAllFeatures` are removed.
- Code generated by `wasm2api` fails initialization when the runtime lacks a feature the module requires, and `*_get_required_features` returns `uint64_t`.
- `wasm_runtime_call_frame` takes a `wasm_module_t** out_module` after `depth`, and any of its outputs may be NULL. In Zig, `CallFrame` has an `instance` field.
- `wasm_free_module` is `wasm_module_free`, and `wasm_module_get_userdata` is `wasm_module_userdata`.
- `wasm_memory_data`, `wasm_memory_size`, and `wasm_memory_grow` take a memory index and replace their `_at` variants.
- `wasm_memory_ref_at`, `wasm_table_ref_at`, and `wasm_global_value_ref_at` are `wasm_module_memory`, `wasm_module_table`, and `wasm_module_global`.
- `wasm_memory_t`, `wasm_table_t`, `wasm_global_t`, `wasm_comptype_t`, `wasm_export_t`, and the segment, tag, custom section, and exception state structs are opaque.
- Module and runtime query functions take `const` pointers, `wasm_module_runtime` returns a non-`const` runtime, and `wasm_import_info_t` names are `const char*`.
- `wasm_shared_memory_free` is now `wasm_memory_free`, which also frees memories from the new `wasm_memory_new`.
- `frame_arena_size` (and `WASM_FRAME_ARENA_SIZE`, now 256 KiB) sets the size of each block of call frame storage. The runtime allocated the largest frame times the call depth limit up front, up to about 750 MB for a module with large frames, and a nested call needing more failed with `WASM_ERR_CALL_STACK_EXHAUSTED`. Blocks are now added as calls nest and released as they return, and running out of memory for a frame fails with `WASM_ERR_OOM`.
- `wasm_error_t` has new last members, `WASM_ERR_INTERRUPTED`, `WASM_YIELD`, and `WASM_ERR_SUSPENDED`.
- A call stopped by fuel or `wasm_runtime_interrupt` stays suspended, and other calls on its runtime fail with `WASM_ERR_SUSPENDED` until `wasm_runtime_resume` or `wasm_runtime_cancel`.
- `wasm_runtime_new` takes a required `wasm_allocator_t` before the configuration; `wasm_libc_allocator()` returns one over `malloc`.
- `WASM_MALLOC`, `WASM_REALLOC`, `WASM_FREE`, `WASM_CALLOC`, `WASM_GC_ALLOC`, and `WASM_GC_FREE` are removed.
- `wasm_memory_new`, `wasm_shared_memory_new`, and `wasm_table_new` take an allocator as their first argument.
- Generated `wasm2api` options have an `allocator` field, defaulting to `wasm_libc_allocator()`.
- In Zig, `Runtime.init` and `SharedMemory.init` take a `std.mem.Allocator` first.
- `wasm_instantiate` takes the runtime to instantiate in and the instance's userdata: `wasm_instantiate(rt, compiled, userdata)`.
- In Zig, `Runtime.bindTag` takes a function type for the tag's payload, and `Instance.structNew` and `Instance.arrayNew` take a tuple of values or a `[]const wasm.Value`.
- In Zig, `Module` is split into `CompiledModule`, which `Runtime.compile` returns, and `Instance`, which `Runtime.load` and `Runtime.instantiate` return. Introspection is on `ModuleInfo`, reached through `info()`, `Module.instantiate` is `Runtime.instantiate`, host functions take a `*wasm.Instance` caller, and `TypedFunc` and `Memory` have an `instance` field.
- `wasm_global_import_t` has a `type_module` field, required when `ref_type` has a type index, naming the module that index refers to.
- `wasm2api` rejects global imports whose reference type has a type index.
- `max_stack_values` counts 8-byte operand stack slots, and a `v128` takes two. A call fails with `WASM_ERR_STACK_OVERFLOW` on entry when the operand stack cannot hold the most values its body can need.
- `wasm_struct_new` fails with `WASM_ERR_TYPE_MISMATCH` for struct types that have a descriptor.
- A funcref to an imported function has the type of the Wasm function the import is bound to, which casts, `call_indirect`, and `call_ref` check.
- An import of a function that `wasm_register_module` registered as a re-exported import matches the type of the Wasm function that defines it while that function's module is loaded.
- `wasm_register_import` and `wasm_register_tag_import` reject a `type_module` from another runtime.
- A host function or tag registered without a type context has a final type in a rec group of its own and matches only imports of that type.
- `wasm_register_import` rejects a function type with type indices but no type context.

### Security

- WASI `proc_raise` returns `NOSYS`. It raised the requested signal in the host process, so a guest could stop or kill its embedder with `SIGKILL` or `SIGSEGV`.
- Values a host function returns must match its import's result types; a mismatch fails the call with `WASM_ERR_TYPE_MISMATCH`. The interpreter pushed them unchecked, so a host returning an `i32` for an `anyref` result handed the guest an arbitrary pointer. Results now start as the zero or null value of their type, so callbacks that set only the payload keep working.
- `wasm_register_tag_import` rejects an `identity` that names no live tag or a tag of another type, and a tag type with type indices but no type context.

### Added

- `wasm2api --check` fails unless the existing `<prefix>.h` and `<prefix>.c` match its output, and writes nothing.
- `./cbuild --regenerate-examples` adds `session_math_regenerate`, which rebuilds `examples/session_math.wasm` and its wrappers with `emcc`, and test runs check the committed wrappers.
- `wasm_runtime_allocator` returns a runtime's copy of its allocator.
- `wasm_runtime_interrupt` stops a running call from any thread with `WASM_ERR_INTERRUPTED`, at the next loop iteration, function entry, `memory.atomic.wait`, or WASI sleep. In Zig, `Runtime.interrupt` and `error.Interrupted`.
- `wasm_ref_hold` and `wasm_ref_release` keep a GC reference, converted `externref`, or `exnref` alive across collections in a slot the collector updates. Collections move objects, so references held only by the host went stale. In Zig, `Runtime.hold`, which returns a `Held`.
- `wasm_register_module` makes an instance's exports importable by later modules in the same runtime. The spec test harness now links modules through it.
- `wasm_table_size`, `wasm_table_get`, `wasm_table_set`, and `wasm_table_grow`; `wasm_global_get_index` and `wasm_global_set_index`, which check mutability and type; and `wasm_call_ref`, which calls a funcref.
- `wasm_memory_new`, `wasm_table_new`, and `wasm_table_free` create and free host memories and tables to register as imports, and `wasm_memory_base` and `wasm_memory_length` read a memory handle's data and size.
- `wasm_instantiate` instantiates a compiled module in any runtime, including runtimes on other threads at the same time, and sets the instance's userdata before its start function runs. In Zig, `Runtime.instantiate`, `Runtime.instantiateContext`, and `Runtime.bindInstanceFunc`, which passes the calling instance's context to a host function.
- `wasm_import_check` reports whether a runtime's bindings resolve an import of a compiled module. In Zig, `Runtime.checkImport` and `Runtime.unresolvedImports`.
- `wasm_func_ref_target` returns the instance and function index a funcref refers to. In Zig, `Runtime.funcRef` and `Runtime.callRef`.
- Zig `ModuleInfo.resolve` returns a `Plan` that binds a struct of typed exports to each instance of a module, `Instance.exportsAs` binds one directly, and `Pool` keeps instances of a compiled module ready with their exports bound.
- `wasm2zig`, installed by `zig build`, generates Zig `Exports` and `Imports` declarations from a Wasm module, and `addBindings` in `build.zig` runs it at build time.

- `examples/zig` builds a C library to Wasm and embeds it from Zig with generated bindings.
- Zig `Runtime.bindAll` and `Runtime.bindAllContext` bind every public function of a namespace, and `checkHost` checks a namespace against import signatures at compile time.
- Zig host functions take `GuestSlice`, `GuestBytes`, and `GuestPtr` parameters for ranges of the caller's memory, and a leading `*Runtime` caller; `Runtime.bindFuncDynamic` binds functions with signatures known at run time.
- Zig `bool`, enum, and packed struct values convert to and from `i32` and `i64`.
- Zig `TypedFunc.start` and `TypedFunc.resumeWith` return an `Outcome` that reports a suspended call.
- Zig `RefType`, `FuncType.paramRefType`, `FuncType.resultRefType`, `Import.ref_type`, `ModuleInfo.globalRefType`, `ModuleInfo.tableRefType`, `ModuleInfo.structField`, and `ModuleInfo.arrayField` describe reference and GC types.
- Zig `Value`, `FuncType`, and `CallFrame` format with `{f}`, and `Runtime.frames` iterates call frames.
- Zig `HostMemory` and `HostTable`, which `Runtime.bindMemory` and `Runtime.bindTable` accept along with `SharedMemory` and instance memories and tables.
- Zig `Table`, `Global`, `Instance.global`, `Runtime.registerModule`, `Runtime.lastError`, `Memory.slice`, `Memory.load`, `Memory.store`, and `Config.features` and `Config.fuel`.
- `wasm_config_t.max_total_memory_bytes` caps the linear memories of all of a runtime's instances together. In Zig, `Config.max_total_memory_bytes`.
- `wasm_config_t.max_gc_heap_bytes` caps the GC heap. In Zig, `Config.max_gc_heap_bytes`.
- Stack switching (`WASM_FEATURE_STACK_SWITCHING`, Zig `Features.stack_switching`): continuation types, tags with results, and `cont.new`, `cont.bind`, `resume`, `suspend`, `switch`, `resume_throw`, and `resume_throw_ref`.

- Backtraces name each frame's module and function from the `name` section, as in `#0 app!parse (func[12]) at offset 0x002A`, and `wasm_func_name` and `wasm_module_name` return those names.

Since 1.2.0 required a preopen for every path operation, no embedder could give a guest file access. In Zig, `Runtime.setWasiArgs`, `setWasiEnv`, and `preopenDir`.

In Zig, `Runtime.resumeCall`, `TypedFunc.resumeCall`, `Runtime.suspended`, `Runtime.cancel`, `error.Yield`, and `error.Suspended`.

- Zig `RefType.exact` and `Import.exact`.
- The CLI `types` command shows descriptor clauses, and the inspection commands mark exact reference types and function imports.
- `./cbuild --gc-stress` builds with `WASM_GC_STRESS`, which collects garbage before every GC allocation.

### Changed

- `wasm2api` skips the Emscripten `setThrew` export by default.
- Bulk instructions cost fuel for their size: a unit per 64 bytes or 8 elements they touch, on top of the unit per instruction. `memory.fill` over 4 GiB cost one unit, so fuel did not bound running time.
- `memory.grow` and `table.grow` within their maximum run out of fuel before growing when the budget cannot cover them.
- `block`, `loop`, and `end` cost no fuel.
- A shared memory a module defines reserves address space only up to `max_memory_bytes`. It reserved its declared maximum, up to 4 GiB, regardless of the limit.
- The interpreter runs `wasm_bench` about 10x faster than 1.2.0. Operands and locals use untagged 8-byte slots, with stack maps tracing references for GC. Translation fuses common local, constant, arithmetic, comparison-and-branch, load/store, and `nop` sequences; calls push and pop frames inline, and indirect calls cache successful type matches.
- A NaN result of `f64.add`, `f64.sub`, `f64.mul`, or `f64.div` carries the payload of its first NaN operand, made quiet.
- Imports bound by `wasm_register_module` call the exporting instance's functions as Wasm calls, and fuel, interrupt, and yield stops inside them suspend the call.
- The CLI inspection commands and `wasm2api` read modules with every implemented proposal enabled.
- With custom descriptors enabled, `br_on_cast` and `br_on_cast_fail` accept a target type that is not a subtype of the operand type when both are in the same type hierarchy.

### Fixed

- `wasm2api --singleton` emitted an empty `*_api_t` struct, which MSVC rejects; it holds `init_error`, the result of `*_init`.
- An exception thrown inside a legacy `catch` or `catch_all` body was caught by a later clause of the same `try`.
- Valid modules using a legacy `delegate` failed validation.
- Imports read freed memory after the `type_module` of a registered function import was freed.
- Global and table imports with concrete reference types rejected valid imports and accepted mismatched ones.
- Type checks rejected another module's GC objects and checked another module's functions against the checking module's types.
- Casts and accesses trapped on GC objects of a freed module, and collections skipped their fields.
- Validation rejected `(ref nofunc)` and `(ref none)` where a non-null concrete reference type was expected.
- A legacy `rethrow` resolved its label wrongly and skipped the handlers of `try` blocks inside the target `catch`.
- `array.new` popped its initial value before allocating the array, so a collection during that allocation missed the value, and the array was filled with a reference into the freed heap.
- The GC frees `externref` boxes made by `extern.convert_any` and the `exnref` objects made by `catch_ref` and `catch_all_ref` once nothing reaches them. Both lived until the runtime was freed and kept what they referred to alive, so a guest loop grew host memory without bound, and `any.convert_extern` slowed down as boxes accumulated.
- Calls that trap set `wasm_runtime_last_error` and `wasm_runtime_error_message`, which reported `ok` after a trap.
- The GC heap grows to hold live objects and allocations larger than its initial size, which failed with `WASM_ERR_OOM` once about 4 MiB was live.
- A collection skips anyref values made by `any.convert_extern` from host `externref` values, which it dereferenced as GC objects and crashed on.
- Collections during instantiation keep the GC objects that constant expressions are building; globals, tables, and element segments could end up referring to freed or reused objects.
- `wasm_struct_new` and `wasm_array_new` keep the references they are given alive while allocating, which a collection during that allocation left pointing at freed objects.
- `extern.convert_any` returns exactly the host `externref` that `any.convert_extern` received; odd values such as 1 came back as a different pointer and tested as `i31ref` in between.
- A host value passed to Wasm as an `externref` or `anyref` could be read as a GC object, and changed by a collection, once a later GC heap covered its address.
- Loading a module whose function body ends where a block type should start read a byte past the module.
- Validating a `br_table` or an unreachable `array.new_fixed` with a count near 2^32 took minutes.
- A host import reached through `call_indirect` or `call_ref` from another module had its results checked against the calling module's type indices, so a valid reference result failed with `WASM_ERR_TYPE_MISMATCH`.
- A collection during a host function call could free or move the objects its reference arguments referred to.
- `global.set`, `table.set`, `table.fill`, and `table.grow` of a typed function reference from another module trapped with a type mismatch.
- The CLI showed `exnref` types as `unknown` and `exnref` values as `<unsupported>`.
- The spec test runner's `assert_exception` passed on any trap.
- Validation accepted `struct.new_default` for struct types with non-defaultable fields.
- `wasm_compile` failed on valid modules whose constant expressions trap.
- `wasm_load` reported a missing or mismatched import, or a trap in a constant expression, for a module that is also malformed or invalid.
- Validation accepted function subtypes whose typed reference parameters or results did not match their supertype's.
- Modules with an export kind above 4 were not rejected as malformed.
- Validation skipped the label type check of a `br_on_cast` whose operand is unreachable.
- Validation accepted modules that used the value a failed `br_on_cast` or `br_on_cast_fail` from `(ref null $t)` to `(ref $t)` passes on as a null bottom reference.
- Validation accepted `array.new_default` for array types whose elements are not defaultable.
- Validation accepted element segments of kind `func` for tables of a concrete function reference type.
- Validation rejected struct and array subtypes whose mutable reference fields name equivalent types by different indices.
- Type checks across modules allocated on every check, and on deep type graphs took seconds when allocation failed.
- Validation checked constant expressions by the values they produce instead of their static types, accepting a `(ref $sub)` global initialized by `global.get` of a `(ref $super)` global.
- Validation accepted `struct.new_default` and `array.new_default` of types with non-defaultable fields in constant expressions.
- Type checks accepted a non-null host value of a bottom reference type such as `WASM_TYPE_NONE` as a reference of any type in its hierarchy.

## [1.2.0] - 2026-10-17

### Security

- WASI path operations accept only directories reached from a preopen. Standard I/O descriptors were treated as directory capabilities, so a guest could open, create, rename, or delete any host file through `path_open(0, "/abs/path")` and the other `path_*` calls. Guest paths, and symlink targets, must now be relative and must not climb above their directory with `..`; violations return `NOTCAPABLE`.

### Added

- `wasm_config_t.max_function_locals` (default 50,000, `WASM_MAX_FUNCTION_LOCALS`) limits the locals a function may declare; 0 removes the limit. A 30-byte module could declare hundreds of millions of locals and make loading allocate gigabytes.
- `wasm_config_t.max_memory_bytes` (default unlimited) and `max_table_elements` (default 10,000,000) cap each memory and table at instantiation and on growth. A module could declare a table of 2³² elements and make loading write every one.
- `wasm_compile` decodes and validates a module without resolving imports or running code, and `wasm_instantiate` creates instances of it without validating function bodies again. Zig exposes them as `Runtime.compile` and `Module.instantiate`.
- The CLI `imports` command. The inspection commands compile instead of instantiating, so they no longer fail on modules with unbound imports or run start functions.
- `wasm_bench`, interpreter micro-benchmarks for loops, memory access, calls, `br_table`, `call_indirect`, and floating point.
- `wasm_exec_fuzzer`, a libFuzzer harness that instantiates each input with stubbed imports and calls its exports, and `wasm_exec_fuzz_replay`, which runs that harness over the seed corpus in `test/fuzz/corpus` as part of `./cbuild --test`.
- `WASM_ERR_EXIT` and `wasm_runtime_exit_code`, which report a guest's requested termination and its status. In Zig, `error.Exit` and `Runtime.exitCode`.
- Zig `Config` fields for `max_function_locals`, `max_memory_bytes`, and `max_table_elements`.

### Changed

- The interpreter is about 25% faster on `wasm_bench` (release build). Single-byte immediates and the common memory-argument form decode inline, numeric locals, parameters, and results skip reference retagging, `br_table` no longer allocates, branches move results without a scratch buffer, block exits skip `free(NULL)`, frames record their position only when execution leaves them, and `call_indirect` and `call_ref` skip the subtype check when the types are identical.

### Fixed

- Modules whose sections repeat or appear out of the binary format's order are malformed. A second export section replaced the first and leaked it; the execution fuzzer found it.
- wasm2api inspects modules with `wasm_compile`. It bound the Emscripten stubs, which reach the host filesystem, and ran the module's start function while generating code, and it failed on modules that import memories or tables.
- `wasm_load` clears the previous error first, so a failure no longer reports a stale message from an earlier one.
- WASI `proc_exit` stops the guest. It used to return to the caller, so programs kept running past `exit()` and the status was lost. The CLI exits with the guest's status.
- Exceptions thrown through an imported function reach Wasm handlers after `call_indirect`, `call_ref`, and the tail calls, not only after `call`. A tail call no longer leaves its own function's handlers in place.
- Freeing a module invalidates the funcrefs that point into it. A funcref kept by the host or stored in a table that outlives the module was resolved through freed memory; using it now traps or fails the type check.
- Public functions given a NULL runtime or module return an error instead of crashing; `wasm_call`, `wasm_call_index`, the `wasm_register_*_import` functions, and the feature toggles dereferenced it.
- Type canonicalization hashes each rec group and compares it only with earlier groups of the same hash. It compared every pair of types and allocated a types² table for each comparison, so a 20 KB module with 2,000 types took over 30 seconds to load.
- Validating functions with non-defaultable locals no longer clears local-initialization state for every possible block depth.
- GC marking uses an explicit worklist instead of recursion, so collecting long object chains no longer overflows the native stack.
- WASI `path_open` derives the host access mode from the requested rights, so directories and read-only files can be opened on POSIX hosts.

## [1.1.0] - 2026-10-17

### Added

- Opt-in support for wide arithmetic, custom page sizes, compact imports, and threads, including shared memories usable from runtimes on separate threads.
- A Zig 0.17 package: `build.zig` compiles the runtime from `src/` with Zig's C compiler, and the `wasm` module wraps the C API with checked typed calls, host functions generated from Zig functions, a Zig error set, and memory, global, introspection, GC, and shared-memory accessors. `zig build test` runs the wrapper tests and the modular C regression tests; `./cbuild --test` runs it as the `zig` test when Zig 0.17 is available. See `docs/ZIG.md`.

### Fixed

- Calls reject arguments that do not match the function parameter types with `WASM_ERR_TYPE_MISMATCH` before execution.
- Bound decoded vector counts and checked array allocation sizes; fixed relaxed SIMD i16 dot-product wrapping.
- Restored warning-clean MSVC builds and fixed 32-bit x86 builds, including 64-bit atomic alignment and handling of allocation failures.
- The WASI `fd_readdir` binding reads entry serial numbers from `d_fileno` on the BSDs, whose `dirent` declares `d_ino` only outside strict POSIX mode; platform builds failed on FreeBSD.

### Changed

- Split the runtime into independently compiled sources under `src/`, with a generated single-header distribution and modular-library tests.
- Updated the WebAssembly testsuite to 2026-10-14 and added proposal-suite coverage.
- The build moved from CMake to [cbuild](https://github.com/grant-wade/cbuild): `build.c` describes the build and test graph and needs only a C compiler. Bootstrap with `cc -o cbuild build.c`; `./cbuild --test` replaces the `check` target. See `docs/BUILDING.md` for the option and target mapping.
- `tools/amalgamate.c` replaces `cmake/Amalgamate.cmake` as the `wasm.h` generator and freshness check, including in the pre-commit hook. Its output is unchanged apart from the regeneration command in the header comment.

### Removed

- The CMake build, its installable package metadata (`find_package(wasm_h)`), and the Makefile wrappers. Install by copying `wasm.h`.
- The non-failing `wasm-spectest-run` and `wasm-emcc-run` variants; `./cbuild --test --test-label=spectest` (or `emcc`) runs a suite and reports failures.

## [1.0.0] - 2026-07-14

Initial public release.

### Security

- Removed the implicit WASI preopen of the host working directory.
- Made WASI bindings opt-in in the CLI.
- Documented that Emscripten syscall shims are for trusted modules only.

### Fixed

- Made Wasm i32/i64 wrapping arithmetic independent of signed C overflow.
- Preserved required quiet-NaN behavior in optimized rounding operations.
- Fixed optimized platform-build warnings and spectest harness leaks.

### Changed

- Removed the opaque prebuilt SQLite Wasm demo; examples are now source-reproducible.
